# Public API control-surface and recovery audit

This manifest is reviewed with `database/migrations/001_initial_schema.sql`,
the PostgreSQL repositories/services, processors and worker consumers, generated
OpenAPI, and the first-party Operator clients. `A` means mutable persisted
resource, `B` immutable financial/evidentiary fact, `C` standalone projection or
protocol, and `D` first-party/internal concern. It records operational control,
not just route presence.

## Account debt policy

Cliqero maintains a canonical USD receivable at the account level; individual
wallet buckets remain non-negative. Recovery consumes safe available account
value first where the owning workflow supports it, and any residual exposure is
recorded as explicit debt. Purchases, withdrawals, and user wallet transfers are
blocked while debt is outstanding; credits and other inflows remain allowed.
Future inflows settle debt before value becomes spendable. Pending purchase
earnings settle debt only when their pending-to-available transition commits.
Increases, settlements, and write-offs are append-only, auditable, idempotent,
and cannot over-settle; write-off is highly privileged.

## Monetary recovery matrix

Every correction is authenticated, leaves original evidence intact, records
actor/reason/correlation and is retriable by a stable idempotency identity.

| Flow / authoritative fact           | Expected effects and transaction                                                                                       | Failure/duplicate/reversal recovery                                                                                                                                                                                                                                                                                                                                                                                                           | API authority and resulting history                                                                  |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Provider funding / provider payment | provider result plus funding/payment row; wallet credit is unique per funding; outbox processing is retriable          | `/api/payment-reconciliations` verifies provider authority and completion processor creates only a missing credit. `/api/funding-reversals` records immutable partial/full provider reversals; pending/missing credits are neutralized, then safe Funding and Earnings balances are reclaimed, with residual exposure recorded as account debt. Reconcile-credit refuses a fully reversed funding and restores only the unreversed remainder. | `payments:manage`; provider event evidence, Funding Reversal, wallet history, debt and audit facts   |
| Wallet transfer                     | transfer fact, wallet legs, earnings adjustment, Treasury fee are one UoW transaction                                  | reverse by original transfer with a unique reversal idempotency key and opposite legs/fee adjustment; preserve original; incomplete until API and DB integration proof exist                                                                                                                                                                                                                                                                  | `wallet:manage` or existing `wallet:transfer` capability; compensation record and correlated history |
| Purchase distribution               | purchase completion and ledger distribution/outbox transaction; each ledger leg idempotent                             | distribution retry repairs missing beneficiaries; signed earnings adjustment corrects wrong beneficiary/amount; purchase reversal appends opposite legs; existing adjustment must link purchase/distribution/beneficiary                                                                                                                                                                                                                      | `finance.manage`/`payments:manage`; adjustment/reversal and audit facts                              |
| Treasury operation                  | source operation and Treasury entry written transactionally                                                            | append signed idempotent adjustment with source/reference/correlation; never rewrite/delete original                                                                                                                                                                                                                                                                                                                                          | `treasury.manage`; adjustment and entry                                                              |
| Withdrawal                          | request reserves available earnings; completion persists external evidence; cancel releases reservation/reconciles fee | a verified full payout return appends a return fact, records a returned reservation event, restores gross value with debt settlement before spendability, reverses the Treasury fee, and marks the withdrawal failed without deleting completion history; a payout which truly left still needs funding-reversal recovery                                                                                                                     | `withdrawals.manage`; reservation/return events, completion evidence, outbox/audit                   |

## Stop conditions found in this pass

This audit is intentionally **not operationally complete**. The following
correction scenarios lack a safe external control path or require an explicit
financial policy before one can be implemented without guessing:

| Scenario                                                               | Current behavior / risk                                                                                                                                                                                                                                                     | Smallest viable policy choices                                                                                                                                                                                                                                                                            |
| ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Provider funding is reversed after its credit was spent or transferred | The Funding Reversal workflow reclaims currently safe available Funding value, then safe available Earnings value, and records any residual as account debt. Funding and Earnings availability exclude existing recovery legs and active/completed withdrawal reservations. | If pending withdrawal value is still reserved, its owning withdrawal workflow must release it; reversal does not directly delete or rewrite reservations. Recovery conservatively leaves that value reserved and records any resulting exposure as debt. Completed/external payouts are not unwound here. |
| Posted wallet transfer is reversed after destination funds are spent   | No wallet-transfer compensation API exists. An inverse transfer may fail for insufficient destination balance and must also reverse the original Treasury fee.                                                                                                              | Implement a correlated compensating transfer/adjustment that preserves the original transfer and Treasury fee history and follows the account debt policy.                                                                                                                                                |
| Funding reversal after a completed payout truly left Cliqero           | The Funding Reversal workflow recovers any other safe available account value and records residual account debt; it does not mutate the completed payout or treat the funding reversal as a payout return.                                                                  | Future inflows settle debt before spendability; the completed withdrawal and provider funding evidence remain intact.                                                                                                                                                                                     |
| Distribution beneficiary/amount is wrong or missing                    | Public signed earnings adjustments are idempotent, but source-linked correction and behavior when earnings are reserved/withdrawn still need further recovery work.                                                                                                         | Complete source-linked earning correction and define behavior when earnings have been reserved/withdrawn.                                                                                                                                                                                                 |

Additional known gaps: wallet-transfer compensation, broader source-linked
earnings correction, unsupported provider-specific reversal event types, and
the complete mutable-resource/API-boundary audits remain open. This checkpoint
supports the configured Paystack `refund.processed` adapter only; it does not
claim chargeback/reversal event support from other providers. Provider refund
principal does not create a Treasury entry because the original funding
principal is a customer-wallet liability, not platform Treasury income. No
refund/chargeback fee is recorded: the normalized event and current fee policy
do not provide a supported attributable fee fact.

Provider-event economic processing and Funding Reversal persistence share one
database transaction. The outbox event is acknowledged only after that
transaction commits; if acknowledgement is interrupted, replay finds the
reversal by provider-event-derived idempotency identity and does not repeat
recovery.

## Delete-pass status

The delete surface uses collection-level DELETE for mutable resources and keeps
immutable distribution, earning-entry, and Treasury-entry facts non-destructive.
Pending media cleanup is hidden from public resource reads immediately; nested
integration DELETE removes only the selected listing association. The wider
control-surface and recovery audit remains in progress.
