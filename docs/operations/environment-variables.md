# Environment variables

[Back to documentation index](../README.md) · [Installation and Configuration](./installation-and-configuration.md)

This is the authoritative reference for Cliqero-owned environment variables
that application, worker, infrastructure, and normal-operation tooling reads
directly. The root [`.env.example`](../../.env.example) is intentionally a
small bootstrap file, not an exhaustive catalogue. Copy it for a normal local
start, then use this page when tuning a deployment or diagnosing a runtime.

Defaults below are the defaults in the current source or Compose files. A
Compose default applies when the variable is not set in the host environment;
an application default applies when the process itself receives no value.

## Application

| Variable       | Required                                               | Default                                                                                                 | Used by                                                 | Description                                                                                                                                     |
| -------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `NODE_ENV`     | No                                                     | Compose: `development` for the web app/worker; application code also recognizes `test` and `production` | Web app, worker, diagnostics                            | Selects runtime behavior such as development diagnostics, secure cookies, and provider eligibility.                                             |
| `APP_URL`      | No locally; required for a non-local/public deployment | `http://localhost:3000` in the server configuration and Compose                                         | Web app, worker, site configuration, provider callbacks | Public application origin used for absolute links, redirects, callbacks, and generated site configuration. Keep it as an origin without a path. |
| `APP_PORT`     | No                                                     | `3000`                                                                                                  | Main Compose service                                    | Host port published for the web app. The container still listens on port `3000`.                                                                |
| `DATABASE_URL` | Yes when starting the app, worker, or CLI directly     | Compose builds it from `POSTGRES_*` and the `postgres` service hostname                                 | Web app, outbox worker, CLI, database seed              | PostgreSQL connection string. Compose supplies an internal connection automatically; host-run processes must receive one explicitly.            |

`NEXT_PUBLIC_SITE_CONFIG` and `NEXT_PUBLIC_AUTH_CONFIG` are generated by the
Next.js configuration from tracked YAML during a build. Do not set them as
operator configuration; change `config/site.yaml` or
`config/security/auth.yaml` instead.

| -------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------- | ------------------------------------------------------------------------------------ |

Change this together with the local connection settings.   |
| `POSTGRES_USER`      | No       | `cliqero`                                                                                                                      | PostgreSQL, Compose connection construction, Adminer | PostgreSQL login role.                                                               |

| `POSTGRES_PORT`      | No       | `5432`                                                                                                                         | PostgreSQL Compose override                          | Host port published for PostgreSQL; the container remains on `5432`.                 |
| `ADMINER_PORT`       | No       | `8080`                                                                                                                         | Adminer Compose service                              | Host port for the optional local Adminer UI.                                         |
| `BLOG_DATABASE_PATH` | No       | Compose: `/workspace/data/blog/blog.sqlite`; application fallback: `data/blog/blog.sqlite` under the project working directory | Blog SQLite infrastructure                           | Path to the independent blog database. It must not point at the PostgreSQL database. |

integration-test recipe supplies `TEST_DATABASE_URL` separately; it does not
change the application database configuration.

## Authentication and security

| Variable             | Required                                                                   | Default                                            | Used by                    | Description                                                                                                                          |
| -------------------- | -------------------------------------------------------------------------- | -------------------------------------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `BETTER_AUTH_SECRET` | Required in production; optional for local Compose bootstrap               | Compose development fallback: a placeholder secret | Better Auth infrastructure | Secret used to sign browser sessions and OAuth state. Use a strong random value of at least 32 characters outside local development. |
| `OPENAPI_KEY`        | No in development; required to authorize schema access outside development | None                                               | OpenAPI security boundary  | Credential for reading the generated OpenAPI schema outside development. It authorizes no business API operation.                    |

Google OAuth credentials are configured in the copied local
`config/security/auth.yaml` module file, not as root environment variables.

## Worker and background processing

These settings are optional. Invalid or non-positive numeric values fall back
to the documented default in the worker.

| Variable                       | Required | Default                             | Used by                                    | Description                                                                                                                              |
| ------------------------------ | -------- | ----------------------------------- | ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `OUTBOX_WORKER_ID`             | No       | Generated as `outbox-<random UUID>` | Outbox worker                              | Stable identity used when the worker claims outbox work. Set it when an operator needs a recognizable worker identity.                   |
| `OUTBOX_BATCH_SIZE`            | No       | `20` items                          | Outbox worker                              | Maximum outbox batch size processed in one dispatcher iteration.                                                                         |
| `OUTBOX_POLL_MS`               | No       | `1000 ms`                           | Outbox/commercial worker                   | Idle delay before the next worker loop when no work was processed.                                                                       |
| `OUTBOX_STALE_AFTER_MS`        | No       | `300000 ms` (5 minutes)             | Outbox worker                              | Age after which an abandoned outbox claim may be treated as stale.                                                                       |
| `OUTBOX_RETRY_BASE_MS`         | No       | `1000 ms`                           | Commercial worker loop                     | Base delay for retry backoff.                                                                                                            |
| `OUTBOX_RETRY_MAX_MS`          | No       | `30000 ms`                          | Commercial worker loop                     | Maximum retry backoff delay.                                                                                                             |
| `FUNDING_VERIFICATION_POLL_MS` | No       | `10000 ms`                          | Application container and funding workflow | Delay used when scheduling the next durable automated funding-verification attempt. This is server-side work; it is not browser polling. |

## Integration and storage configuration

| Variable     | Required                                                | Default                                                               | Used by                                                                             | Description                                                                                                                      |
| ------------ | ------------------------------------------------------- | --------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `TUNNEL_URL` | Only when a configured provider needs a public callback | Empty in local Compose                                                | Main/worker development Compose overrides and callback-bearing module configuration | Base public tunnel origin for local server-to-server callbacks. Keep provider paths in YAML; do not put a path in this variable. |
| `MEDIA_ROOT` | No when the filesystem storage default is suitable      | `/var/lib/cliqero/media` outside tests; `/tmp/cliqero-media` in tests | Filesystem storage configuration                                                    | Root directory for the configured local media storage instance. The tracked media example shows how it is substituted.           |

Payment credentials and provider-specific settings are intentionally owned by
the relevant tracked configuration examples under
`config/modules/payment/`, `config/modules/payout/`, and
`config/storage/`. Copy the applicable example to its ignored runtime YAML and
follow its comments. Do not add provider secrets to this file or to
`.env.example`. `APP_URL`, `TUNNEL_URL`, and `MEDIA_ROOT` are listed above
because they also affect application/Compose runtime behavior.

## Logging and diagnostics

| Variable                    | Required | Default                 | Used by                       | Description                                                                                                                                                     |
| --------------------------- | -------- | ----------------------- | ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DEVELOPMENT_LOG_MAX_BYTES` | No       | `5242880` bytes (5 MiB) | Development diagnostic logger | Per-file size cap for development diagnostic logs. A missing, invalid, non-integer, or non-positive value safely uses the default; logging remains best effort. |

The development diagnostic logger is enabled only when `NODE_ENV=development`.
It is not a production log rotation setting.

## Testing and diagnostics tooling

| Variable            | Required                   | Default                                                                          | Used by                  | Description                                                                                                                       |
| ------------------- | -------------------------- | -------------------------------------------------------------------------------- | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| `TEST_DATABASE_URL` | Only for integration tests | `postgresql://cliqero:cliqero-local@localhost:5432/cliqero` in the `just` recipe | Integration test command | PostgreSQL connection used by the shared integration test database. It is test-only and is not application runtime configuration. |

## Configuration ownership rule

Environment values referenced through `%env(NAME)%` in tracked module or
provider YAML are documented by that configuration example and the relevant
provider documentation. They do not need to be duplicated in `.env.example`
or enumerated as a second secret catalogue here. The YAML loader resolves them
from the process environment and reports missing values with configuration
context.

When introducing a new directly-consumed Cliqero runtime variable, update this
reference in the same change. Add it to `.env.example` only when it is needed
for normal bootstrap, commonly configured, or important enough for immediate
operator visibility.
